COMMIT Demonstration

PERMANENT PERSISTENCE

Increments demo account balance by ₹1,000.00, creates a committed transaction log, and issues an explicit COMMIT statement. All locks are released and redo is flushed to disk.

UPDATE bank_accounts SET balance = balance + 1000;
COMMIT;

ROLLBACK Demonstration

COMPLETE REVERSAL

Tentatively modifies the balance by +₹2,000.00 in Oracle memory buffer cache, then immediately issues a ROLLBACK statement. The database state reverts to prior value with zero disk change.

UPDATE bank_accounts SET balance = balance + 2000;
ROLLBACK;

SAVEPOINT Demonstration

PARTIAL ROLLBACK

Applies +₹1,000.00, establishes SAVEPOINT intermediate_state, attempts +₹2,000.00, then executes ROLLBACK TO SAVEPOINT. Only step 1 (+₹1,000) is saved; step 2 is discarded.

UPDATE ... balance + 1000;
SAVEPOINT intermediate;
UPDATE ... balance + 2000;
ROLLBACK TO intermediate;
COMMIT;

Theoretical Foundation: The ACID Model in Banking Systems

A
Atomicity ("All or Nothing")

A multi-step banking transfer either completes entirely (both debit and credit) or none of its modifications persist. Managed via COMMIT and ROLLBACK.

C
Consistency (Integrity Constraints)

The database never violates predefined integrity rules: balance >= 0, foreign key references, and positive transaction values are strictly enforced by Oracle engine.

I
Isolation (Multi-User Concurrency)

Concurrent transactions operate without reading uncommitted dirty data. Implemented with SELECT ... FOR UPDATE row-level exclusive locks.

D
Durability (Redo Log & Checkpointing)

Once a transaction commits, its modifications are permanently recorded in Oracle Redo Log buffers and survive system crashes, power loss, or reboot.
